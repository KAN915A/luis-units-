## Working plan (until pages 2–4 arrive)

1. **Do not start writing evidence** until we see the exact P/M/D task list on pages 2–4 — every mark comes from the criteria phrasing.
2. Meanwhile, from the scenario alone, we can **prepare** the following artefacts (which are almost certain to be asked for on a Unit 22 analysis-and-design assignment):
   - **Requirements specification** — functional + non-functional, categorised, SMART (Unit 3 A2).
   - **Stakeholder table** — client, users, supplier, third parties (Unit 3 B2).
   - **Context DFD (level 0)** + **level 1 DFD** — external entities (Customer, Recipient, Social Media, Payment) around the e-card system (Topic 5 + Topic 7).
   - **ERD** — entities (Customer, Card, Diary Event, Address Book Contact, Order/Receipt) with relationships and cardinality (Topic 4 + Topic 8).
   - **Data dictionary** — one entry per stored field (Topic 4).
   - **Prototype / wireframes** — key screens (dashboard, card personaliser, diary, address book, checkout). Relevant if RAD/prototyping is asked for (Topics 17–18).
   - **Choice of methodology + justification** — Process-Oriented / Data-Oriented / hybrid; Waterfall vs Prototyping/RAD (Topics 7–8, 17).
3. Track each artefact against the P/M/D criteria once the task list is captured.

## Distinction habits (roll-up from Week 1)

- Every model refers to the Say-It-With-Cards scenario directly.
- Every design choice is justified against **alternatives**.
- ERD, DFD and data dictionary **cross-check** each other.
- Recommendation is written and traceable back to the brief.
- **People + Methods + Information Technology** all considered — not just IT.

## Distinction rubric (reminder)

- Evaluates the problem (not just describes).
- Detailed and complex solution — meets **all** scenario requirements.
- In-depth understanding of analysis and design documentation.
- Justified recommendations for future actions.
